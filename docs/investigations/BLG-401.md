# BLG-401: pre-tool text and thinking

Investigation on 2026-11-01. The reported live session's raw events were not
available to this worker. The reported Question 5 has therefore not been traced
to a specific engine item; this is not a confirmed fix of the live issue.

The source paths distinguish messages from reasoning:

- `runner/internal/daemon/claudecode.go`, `emitAssistantBlocks`: Claude `text`
  blocks become `assistant_text` unchanged; only `thinking` blocks become
  `assistant_thinking`.
- `runner/internal/daemon/codexapp.go`, `appItem`: Codex `agentMessage.text`
  becomes `assistant_text` unchanged. Codex `reasoning.summary` is joined with
  newlines and becomes `assistant_thinking`. In this path the engine supplies
  the summary; Blerg does not have an original public message to reconstruct
  from that summary. It must not relabel reasoning as a public answer.
- `packages/chat/src/model/toolGroups.ts`: both event kinds are timeline cards
  and split tool groups. Tool grouping does not convert text into thinking.
- `packages/chat/src/components/cards/EventCards.tsx`: `assistant_text` uses
  the Markdown renderer directly. Only `assistant_thinking` gets the thinking
  footer. Neither path paraphrases text.
- `runner/internal/daemon/verbosity.go`: verbosity appends generation
  instructions to the engine prompt. It does not rewrite received events.
  Terse asks for quiet routine progress but retains required questions.
- `packages/chat/src/components/Transcript.tsx`: hiding thinking filters only
  `assistant_thinking`; it leaves ordinary messages visible.

`runner/frontend/src/components/AgentText.browser.test.tsx` exercises the real
ChatView timeline at 390 and 3840 px, with compact tools on and off, and toggles
thinking visibility. It checks that a complete pre-tool question stays an
ordinary message and actual thinking retains its own caption.

installed build and transport against this checkout. No speculative production

## Evidence from the live session

The reported text is stored as `assistant_thinking` in `agent_events`, already
shortened, and no `assistant_text` event holds the full message. So it reached
the daemon that way from the engine; Blerg didn't relabel it. Until an engine
delivers pre-tool text as text, agents should put questions in the last message
of a turn, which arrives as `assistant_text`.
