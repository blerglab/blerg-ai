This is the fifth release candidate for Blerg 0.6.0. Use it for deliberate upgrade testing with a backup and a recovery plan. It is not offered as an upgrade to 0.5.x installs.

## Changes since rc.4

- Failed workers show their own names and offer Discard or Retry without making the whole workspace look failed (BLG-751).
- The Files panel in a scratch workspace stops loading and explains failures (BLG-752).
- Chat stays still while you type, messages stream, and status changes (BLG-753).
- Workspaces restore the tab you last opened; direct links take priority (BLG-754).
- Chat tables keep short words whole, wrap long links and hashes, and keep export controls clear of content (BLG-755).
- Cluster clones retry temporary failures, report the cause, keep tool temporary files off the runner's temporary volume, and clean up failed jobs (BLG-756).
- Returning to a workspace shows the latest chat promptly (BLG-757).
- Resuming after eviction preserves the retained checkout and unfinished work. If verification fails, resume stops and names the recovery location (BLG-758).
- After a host restart, refused input returns to the composer once, and orphaned sessions can be ended (BLG-760).
- Standing permissions stay unavailable during Core restarts instead of appearing expired. Notices follow the original grant, arrive in order, and preserve exact discovery errors (BLG-764).
- Permission history lookups use an index that can be added safely while the runner is online and reused on repeated starts (BLG-767).
- Reconnecting daemons replay pending input and repair tokens outside the authority lock, with urgent work first, bounded batches, and safe failure diagnostics (BLG-768).
- Large repositories appear in discovery and can be browsed: the Git index is read as a stream with bounded memory and cached safely, instead of hiding any repository whose index exceeds 1 MiB (BLG-775).
- The sidebar History section counts workspaces, folds archived workers under their workspace, and starts collapsed (BLG-778).
- One mouse-wheel notch scrolls up from the bottom of a chat, even while output streams (BLG-786).
- Workspace and new-repository guidance reaches the agent as context instead of appearing as your first message, and the ready card lists the workspace's repositories (BLG-789).
- Ending a session no longer fails while a usage-limit resume is in progress.
- CONTRIBUTORS.md names the people whose contributions shaped Blerg.

Standing permissions survive signing in again to the same account. Permissions distinguishes suspended, expired, and unavailable access and labels ticket-board access as “Ticket board” (BLG-748).

The BLG-758 backport preserves retained checkouts and reports verification failures, but does not export result bundles at shutdown. That portion depends on newer infrastructure absent from rc.4. Turn-end bundle delivery and the rc.4 workspace protocol remain unchanged. The chat package uses the rc version line, 1.59.68.

BLG-764 adds only the unchanged migration 196 for durable permission observations. A later upgrade can apply the intervening dev migrations without a numbering collision; this upgrade path was tested. The rc uses existing board discovery and leaves an absent board unavailable when it cannot verify access. Dev-only board ownership checks and Blackboard management are omitted.

## Known issues

- The owner shell does not open in cluster workspaces (the pod refuses the shell binding). Agents in those workspaces are unaffected. Fixed for rc.6 (BLG-795).
- On macOS with Docker Desktop, Docker-sandboxed sessions fail to start because Docker Desktop keeps reporting a just-created session folder as missing (BLG-784).

## How to upgrade

Back up all three databases, settings and daemon credentials first. Migrations run forward on startup; do not restart older binaries against migrated databases. Stop active agent sessions and save shell work before upgrading. Retain the old commit and matching backups for recovery; see [backup and restore](https://github.com/blerglab/blerg-ai/blob/v0.6.0-rc.5/docs/backup-and-restore.md).

Update the server before separate desktop daemons. This candidate requires an explicit tag checkout: the desktop `--upgrade` command selects stable releases and must not be used to select this RC.

**Desktop** (from the root of your clone):

```sh
git fetch --tags
git checkout v0.6.0-rc.5
cd install/desktop
./blerg-up.sh
```

`blerg-up.sh` rebuilds the stack, runs migrations on service startup, and reinstalls the desktop daemon. **The desktop daemon must be reinstalled** to enable the new behavior. If you used `--no-daemon`, run `./daemon/install.sh install` afterward. Python 3 is required for desktop builds and daemon installation. A new desktop must complete enrollment; use Settings → Account → Your desktops for its one-time command. Reload the browser after the stack and daemon reconnect.

**Kubernetes** (from the root of your clone):

```sh
git fetch --tags
git checkout v0.6.0-rc.5
cd install/k8s
# Back up first and record the currently deployed images and configuration.
# Set TAG=v0.6.0-rc.5 in .env, retaining your existing registry and other settings.
./deploy.sh
```

`deploy.sh` builds and pushes the images and rolls core, runner and board together; migrations run on startup. Keep the agent image on the same candidate. Follow [Rolling back an upgrade](https://github.com/blerglab/blerg-ai/blob/v0.6.0-rc.5/install/k8s/README.md#rolling-back-an-upgrade) for recovery; `kubectl rollout undo` does not undo a full deployment or its migrations. After updating the server, check out the same tag on every connected desktop and run `(cd install/desktop && ./daemon/install.sh install)`.

Upgrade changes and operator choices:

- Shell-tab names use runner migration 104. Push subscriptions created before runner migration 105 cannot deliver until each browser opens the app and re-registers. Core migration 107 gives existing accounts the 0.5.4 What's New baseline. Services apply their bundled migrations automatically.
- Terminal sessions have been removed. Their history stays readable, but they cannot resume. Existing host tmux sessions are left running and logged once at daemon startup: save any work, then stop each manually with `tmux kill-session -t '=blerg-<session-id>'`.
- Reinstall older daemons to enable worker-question routing through Main; older daemons retain the 0.5.4 routing behavior until their next updated connection.
- Privileged Linux host shells are optional: enable `BLERG_HOST_SHELL_CGROUP=1` on the daemon, then explicitly choose and confirm **New privileged host shell**. Ordinary shells retain tracing. Privileged shells are not frozen at turn end. Persistent owner shells refuse recognized WSL and Docker Desktop kernels; restart recovery remains gated off.
- The Board Git panel now requires an open linked workspace; Git hosting links alone no longer fetch commits. The named cluster target retains the default for older clients, with no required target configuration change.

Full list of changes: [CHANGELOG.md](https://github.com/blerglab/blerg-ai/blob/v0.6.0-rc.5/CHANGELOG.md#060-rc5---2026-11-16).
