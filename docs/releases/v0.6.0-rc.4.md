This is the fourth release candidate for Blerg 0.6.0. It is a GitHub pre-release and is not offered as an upgrade to 0.5.x installs. Use it for deliberate upgrade testing with a backup and a recovery plan.

## Changes since rc.3

- Main can propose a new milestone through an owner-bound approval; proposing alone never changes the plan.
- Removing a board card from milestone scope requires a reason, without an unnecessary destination.
- The blackboard and agent API default to the newest open milestone while preserving explicit selections.
- Milestone proposals and approvals load board release evidence and report named checks when evidence is missing.
- Invalid plan proposals name the field and rule to correct, with updated planning guidance.
- The blackboard lists every milestone in its navigation, so a newly opened milestone is always reachable.
- Pending plan approvals no longer mark the cards Main has worked on as "Needs you".
- Channels and worker views open files, diffs, reviews and commit views in tabs beside the chat, as Main does, instead of a modal (BLG-743).
- A new product-phase skill scales planning and testing to the product's declared phase: focused checks while building and full suites once per batch for early products, with security rigor unchanged at every phase (BLG-718).

## Highlights

- **A workspace with Main, channels and workers.** Keep the main task with Main, open named channels, and follow worker progress and failures in the dock. Decisions that need you stay in Needs you.
- **A plan you can follow.** The blackboard brings milestones and linked cards together. Main asks you to approve exact plan proposals.
- **More ways to read and share.** Charts and diagrams open alongside your work, board releases have progress charts, and live board tabs open ticket details that fill the content area on phones. Print viewer content and download messages as Markdown.
- **Your workspace arrangement.** Save named layouts in this browser and restore tabs, splits and panel sizes. Name shell tabs, organize channels into categories, and choose workspace colors and account themes.
- **Faster to return to work.** Startup connects promptly after silent sign-in renewal; warm workspace switches avoid reparsing Markdown, and typing avoids unrelated panel updates.
- **Boards closer to the work.** Track releases, estimates, reviews and failures, and read linked local commits and diffs without a Git hosting token.

## How to upgrade

Back up all three databases, settings and daemon credentials first. Migrations run forward on startup; do not restart older binaries against migrated databases. Stop active agent sessions and save shell work before upgrading. Retain the old commit and matching backups for recovery; see [backup and restore](https://github.com/blerglab/blerg-ai/blob/v0.6.0-rc.4/docs/backup-and-restore.md).

Update the server before separate desktop daemons. This candidate requires an explicit tag checkout: the desktop `--upgrade` command selects stable releases and must not be used to select this RC.

**Desktop** (from the root of your clone):

```sh
git fetch --tags
git checkout v0.6.0-rc.4
cd install/desktop
./blerg-up.sh
```

`blerg-up.sh` rebuilds the stack, runs migrations on service startup, and reinstalls the desktop daemon. **The desktop daemon must be reinstalled** to enable the new behavior. If you used `--no-daemon`, run `./daemon/install.sh install` afterward. Python 3 is required for desktop builds and daemon installation. A new desktop must complete enrollment; use Settings → Account → Your desktops for its one-time command. Reload the browser after the stack and daemon reconnect.

**Kubernetes** (from the root of your clone):

```sh
git fetch --tags
git checkout v0.6.0-rc.4
cd install/k8s
# Back up first and record the currently deployed images and configuration.
# Set TAG=v0.6.0-rc.4 in .env, retaining your existing registry and other settings.
./deploy.sh
```

`deploy.sh` builds and pushes the images and rolls core, runner and board together; migrations run on startup. Keep the agent image on the same candidate. Follow [Rolling back an upgrade](https://github.com/blerglab/blerg-ai/blob/v0.6.0-rc.4/install/k8s/README.md#rolling-back-an-upgrade) for recovery; `kubectl rollout undo` does not undo a full deployment or its migrations. After updating the server, check out the same tag on every connected desktop and run `(cd install/desktop && ./daemon/install.sh install)`.

Upgrade changes and operator choices:

- Shell-tab names use runner migration 104. Push subscriptions created before runner migration 105 cannot deliver until each browser opens the app and re-registers. Core migration 107 gives existing accounts the 0.5.4 What's New baseline. Services apply their bundled migrations automatically.
- Terminal sessions have been removed. Their history stays readable, but they cannot resume. Existing host tmux sessions are left running and logged once at daemon startup: save any work, then stop each manually with `tmux kill-session -t '=blerg-<session-id>'`.
- Reinstall older daemons to enable worker-question routing through Main; older daemons retain the 0.5.4 routing behavior until their next updated connection.
- Privileged Linux host shells are optional: enable `BLERG_HOST_SHELL_CGROUP=1` on the daemon, then explicitly choose and confirm **New privileged host shell**. Ordinary shells retain tracing. Privileged shells are not frozen at turn end. Persistent owner shells refuse recognized WSL and Docker Desktop kernels; restart recovery remains gated off.
- The Board Git panel now requires an open linked workspace; Git hosting links alone no longer fetch commits. The named cluster target retains the default for older clients, with no required target configuration change.

Full list of changes: [CHANGELOG.md](https://github.com/blerglab/blerg-ai/blob/v0.6.0-rc.4/CHANGELOG.md#060---2026-11-07).
