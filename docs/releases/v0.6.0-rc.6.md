This is the sixth release candidate for Blerg 0.6.0. Use it for deliberate upgrade testing with a backup and a recovery plan. It is not offered as an upgrade to 0.5.x installs.

## Changes since rc.5

- Owner shells open in cluster workspaces; cluster refusals no longer give desktop instructions (BLG-795).
- Desktop heartbeats and status updates no longer stall behind the authority lock, preventing deadlocks between pools (BLG-777).

## Known issues

- On macOS with Docker Desktop, Docker-sandboxed sessions fail to start because Docker Desktop keeps reporting a just-created session folder as missing (BLG-784).

## How to upgrade

Back up all three databases, settings and daemon credentials first. Migrations run forward on startup; do not restart older binaries against migrated databases. Stop active agent sessions and save shell work before upgrading. Retain the old commit and matching backups for recovery; see [backup and restore](https://github.com/blerglab/blerg-ai/blob/v0.6.0-rc.6/docs/backup-and-restore.md).

Update the server before separate desktop daemons. This candidate requires an explicit tag checkout: the desktop `--upgrade` command selects stable releases and must not be used to select this RC.

**Desktop** (from the root of your clone):

```sh
git fetch --tags
git checkout v0.6.0-rc.6
cd install/desktop
./blerg-up.sh
```

`blerg-up.sh` rebuilds the stack, runs migrations on service startup, and reinstalls the desktop daemon. A daemon already on rc.5 needs no reinstall for rc.6: both fixes are in the server and frontend. If upgrading from rc.4 or earlier, **reinstall the desktop daemon**. If you used `--no-daemon`, run `./daemon/install.sh install` afterward. Python 3 is required for desktop builds and daemon installation. A new desktop must complete enrollment; use Settings → Account → Your desktops for its one-time command. Reload the browser after the stack and daemon reconnect.

**Kubernetes** (from the root of your clone):

```sh
git fetch --tags
git checkout v0.6.0-rc.6
cd install/k8s
# Back up first and record the currently deployed images and configuration.
# Set TAG=v0.6.0-rc.6 in .env, retaining your existing registry and other settings.
./deploy.sh
```

`deploy.sh` builds and pushes the images and rolls core, runner and board together; migrations run on startup. Keep the agent image on the same candidate. Follow [Rolling back an upgrade](https://github.com/blerglab/blerg-ai/blob/v0.6.0-rc.6/install/k8s/README.md#rolling-back-an-upgrade) for recovery; `kubectl rollout undo` does not undo a full deployment or its migrations. After updating the server, connected desktops already on rc.5 need no daemon reinstall for rc.6. For desktops on rc.4 or earlier, check out the same tag and run `(cd install/desktop && ./daemon/install.sh install)`.

Upgrade changes and operator choices:

- Shell-tab names use runner migration 104. Push subscriptions created before runner migration 105 cannot deliver until each browser opens the app and re-registers. Core migration 107 gives existing accounts the 0.5.4 What's New baseline. Services apply their bundled migrations automatically.
- Terminal sessions have been removed. Their history stays readable, but they cannot resume. Existing host tmux sessions are left running and logged once at daemon startup: save any work, then stop each manually with `tmux kill-session -t '=blerg-<session-id>'`.
- Reinstall older daemons to enable worker-question routing through Main; older daemons retain the 0.5.4 routing behavior until their next updated connection.
- Privileged Linux host shells are optional: enable `BLERG_HOST_SHELL_CGROUP=1` on the daemon, then explicitly choose and confirm **New privileged host shell**. Ordinary shells retain tracing. Privileged shells are not frozen at turn end. Persistent owner shells refuse recognized WSL and Docker Desktop kernels; restart recovery remains gated off.
- The Board Git panel now requires an open linked workspace; Git hosting links alone no longer fetch commits. The named cluster target retains the default for older clients, with no required target configuration change.
