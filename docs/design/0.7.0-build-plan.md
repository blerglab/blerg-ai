# 0.7.0 build plan

Status: plan of record, 2026-11-09. It slices the six reviewed designs (`team-scope.md`,
`accounts-and-placement.md`, `managed-install.md`, `credential-handling.md`, `sign-in.md`,
`merge-queue-and-delivery.md`) into small increments. Each slice is stopped, reported and merged
alone, by one worker per card. Order (owner): install and sign-in, then team scope and claims, then
personal credentials with the Claude seat host, then the merge queue. Where a design's
"Simplification" or "Scope moved to 0.8.0" section conflicts with earlier text, that section wins.

Rule: a slice marked with a note (N1–N10) starts only after its note is written, attacked by
another model, and its findings turned into tests. UI slices go straight to building.

Starting points found in the repo (2026-11-09): there is no Helm chart and no mail, SMTP or TOTP
code yet. Core already has a `projects` table (`core/internal/db/migrations/003_projects.sql`, name
unique per install, four roles), and Board's agent tokens use "project" to mean a board
(`board/internal/api/scope.go`).

## Hard-rules notes

Each note pins these rules plus a test matrix. Each is attacked by another model before its lane starts.

- **N1 install secrets:**
  - Keys are generated only when no data exists.
  - A denied read counts as unknown.
  - No secret appears in values, notes, dry runs or Helm history.
  - Changing values never creates or promotes an account.
  - External database mode renders no database resources.
  - Uninstall keeps Secrets and volumes.
- **N2 email and links:**
  - Links use only the canonical address.
  - Tokens are redeemed only by POST after a landing page and never logged.
  - Recipients are verified Blerg addresses, rechecked at send.
  - One deduplicated outbox entry per incident.
  - Uniform rate-limited responses.
  - Failures are visible to admins.
- **N3 sign-in and recovery:**
  - A factor becomes active only after proof.
  - A reset never removes the factor.
  - Resets revoke across the three services.
  - Step-up needs password plus code; a token never counts.
  - Org admin factor resets have bounded reach.
  - Invites bind to one address and revalidate roles.
  - Break-glass is a link, audited, and all admins are emailed.
- **N4 authority and isolation:**
  - Grants flow down their own tree only.
  - Install admin carries no org rights.
  - Org admins don't use items without membership, and their actions are recorded "via org admin".
  - Core alone mutates grants.
  - Caches older than 30 seconds fail closed.
  - Every org-owned reference is checked against the session's org.
  - Upgrade activates nothing.
- **N5 claims and completion:**
  - Claiming is atomic with a generation; stale updates are refused.
  - One workspace copy per claim.
  - Only named fields flow back.
  - Completion matches the generation, criteria version, rules version and manifest revision atomically.
  - Reopen is authorized and idempotent.
- **N6 leases and revocation:**
  - Renew every 10 s; renewal is refused after a revocation.
  - Self-stop after 30 s without renewal, keeping the workspace and transcript.
  - Capacity is reused only on proof.
  - A disabled account's daemon is accepted only after its sessions are confirmed stopped.
  - Daemons that cannot self-fence run no team work.
  - The minimum daemon version and its capabilities are defined here.
- **N7 AI credentials and the seat host:**
  - Owner-only use, checked at every hand-out.
  - A single generation-fenced refresh authority per provider (see call 1).
  - A different provider account requires an explicit replace.
  - Refresh tokens never enter a session.
  - A worker never switches cards by itself.
  - Changing Main's card means a fresh conversation.
  - Browser sign-in is a single-use transaction.
- **N8 Git tokens:**
  - Reachability is checked only against repositories on projects the owner can read.
  - Never substitute another person's or a shared credential (call 4).
  - The token is used only by the trusted push step and the owner's own clone.
  - A fetch failure is never read as access or as no access.
- **N9 merge queue:**
  - Compare-and-swap push of the exact tested candidate.
  - Reconcile before retrying.
  - Gate jobs are credential-free and isolated.
  - Authority is rechecked before each gate and before the push, failing closed.
  - Only product failures go back to Main.
  - First-return priority only.
- **N10 backup and upgrade:**
  - The checkpoint is written inside the snapshot.
  - A journal gap stops the restore.
  - A restore starts inert.
  - No rollback across an incompatible migration.
  - Key rotation never overlaps a backup or an upgrade.

## Main's calls on gaps found while slicing (2026-11-09)

These are Main's decisions; the owner may overrule any of them.

1. **Refresh authority.** For Claude, the seat host is the only refresh authority: the official CLI renews, and Core keeps no Claude refresh token. Core fences each seat by generation and hands out access copies only from the seat's current generation. Each seat host is its own pod with its state on a volume. A restore doesn't bring seat state back; the person signs in again. For Codex, Core renews. This replaces the "Core stores and renews" wording in `credential-handling.md` goal 2 for Claude.
2. **The same login on several cards** stays unproven until drill 3.1. If the drill fails, a second card on the same provider account is refused, with the reason.
3. **Legacy projects** migrate into the default org. Owner and maintainer become admin, and member and viewer keep their roles. Names become unique per org. In Board's token scopes, "project" is renamed "board", with the old name accepted as an alias.
4. **The operator's shared Git credential** is refused for project work (queue pushes and reachability checks). It stays available for non-project use.
5. **Teamspace compute** is skipped in 0.7.0. The model has no compute row; hardware is 0.8.0.
6. **Activation:** creating a team, or inviting a second person, shows the team pages.
7. **Gates need the cluster runtime.** With it off, the merge queue is unavailable and project settings say why.
8. **The merge queue keeps its own lease records.** Admission now covers runtimes only.
9. **Email is SMTP only in 0.7.0.** Common providers offer SMTP, including on port 2525; HTTP adapters are 0.8.0.
10. **Password reset in phase 1** uses the existing revoke-everywhere path. The 30-second stop guarantee arrives with 2.9.
11. **Install verify** passes with a database restore point plus a file snapshot. The journal and checkpoint (1.18) must land before the alpha gate.
12. **Review rule for merges** (owner, 2026-11-09: "an orchestrator decision; prefer different provider, but account for single-provider installs and users"). The claimer's Main picks the reviewer, in this order:
    1. a different provider, if the person has a credential for one;
    2. otherwise a different model from the same provider;
    3. otherwise the same model in a fresh, separate session given only the diff and the card.

    The review record names the builder's and the reviewer's provider and model, and which case applied, so a same-provider review is visible on the card and in the queue. It is never blocked.
